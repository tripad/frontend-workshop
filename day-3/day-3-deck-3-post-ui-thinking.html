Post-UI Thinking

When the screen isn't the answer.

For two decades, design meant designing screens. Wireframes. Mockups. Prototypes. Every flow began on a screen and ended on a screen.

That paradigm isn't dying. But it's no longer the default. AI has unlocked interfaces that aren't screens — and screens that show up differently than they used to.

If we had another day, we'd build something in each of these new modes. We don't, so we'll do a quick tour. Five patterns. One question to walk away with.

The thesis

The screen had a monopoly.

It's breaking.

Since 2007, the screen — phone, laptop, watch — has been the unit of UX. Every product had a screen. Every flow ended at a screen. Designers thought in screens. That's still mostly true.

But "mostly" is doing more work every year.

Sometimes the answer is still a screen. Sometimes — and increasingly — it isn't.

Old default

what does the screen for this look like?

New question

what's the right interface for this task?

Pattern 01

1.Chat-as-product.

The whole product is a conversation.

No dashboard. No nav. No sitemap. Just a text field and a thread.

  • →ChatGPT, Claude, Perplexity, Pi
  • →Character.ai, Replika
  • →Increasingly: enterprise tools (SQL via chat, internal Q&A, support agents)

For decades we taught users to navigate. Now we're teaching them to converse.

Pattern 02

2.Voice-first.

The UI didn't disappear. It relocated.

To timing. To prosody. To turn-taking. To error recovery. The screen is gone or secondary; the design problem isn't.

  • →ChatGPT voice mode, Claude voice
  • →Granola (meeting AI), Plaud (recorder)
  • →AirPods Live Translate, Apple's redesigned Siri
  • →Smart-glasses cohort (Meta Ray-Ban, Even Realities)

Voice was supposed to die after Alexa flopped. AI made it interesting again — because the agent on the other end can finally hold a conversation.

Pattern 03

3.Generative UI.

The interface is built on demand.

The screen isn't gone. It's just no longer pre-drawn. The agent assembles a UI for this user, this task, this moment — from constraints and components you authored.

  • →Vercel v0, Claude Artifacts
  • →Anthropic Computer Use
  • →Tldraw "make real," Figma AI features
  • →Increasingly: real apps where parts of the UI are generated per session

Your design system used to be a Figma library. Now it's also a contract with an LLM.

Pattern 04

4.Ambient and action-first.

Sometimes the right interface is no interface.

The user states intent. The system figures out where, when, and how. The screen, if there is one, becomes a confirmation surface — not a primary interface.

  • →Limitless, Friend (wearables that listen ambiently)
  • →Rabbit (agentic OS)
  • →Humane AI Pin (failed, but instructive)
  • →Smart home + agent layer (the next iteration of "Hey, Google")

Maybe the screen was always a workaround for not having a better way to say what you meant.

Pattern 05

5.Embedded AI.

The pragmatic majority. The actual job.

Existing screen-based products with AI baked in. Not a new paradigm — but a hundred new design problems inside the old one.

  • →Linear AI, Notion AI, Figma AI
  • →GitHub Copilot, Cursor's inline edits
  • →Slack's AI summaries, Gmail's AI replies
  • →Every SaaS product shipping in 2025

This is where most designers will spend the next five years. The job: where does the AI surface live? When is it visible? When is it hidden? What's the undo? How do you signal that AI happened?

A useful skeptical note

UI isn't dying. Its monopoly is.

Know which is which.

Screens are dead.

The screen still wins for

Information density Parallel comparison Spatial control Sustained focus Visual judgment

"Screens are dead" is hype. They aren't.

The screen wins, decisively, for tasks with high information density, parallel comparison, precise spatial control, sustained focus, or visual aesthetic judgment.

Spreadsheets won't become conversations. Code won't be voice-driven. Photoshop won't be a chat. Most of what you've designed in school will still be screens.

What's actually shifting: some tasks — research, scheduling, coordination, casual queries, simple actions — are leaving the screen, or relocating to it differently. Designers who can spot which task belongs where are the ones who'll matter.

design the post-UI future

design the right interface for this specific task

The skill is being able to argue for a screen, or against one, with reasons.

Takeaway

What's the right interface for this task?

That's the question, now.

For twenty years, designers asked

what does the screen for this look like?

The next twenty years, the question changes

what's the right interface for this task?

Sometimes the answer is a screen. Sometimes a conversation. Sometimes a voice exchange. Sometimes a workflow that runs without you watching. Sometimes nothing — just an action that happens.

Knowing which is which is the new design skill. Spending two minutes asking the question, before reaching for Figma, is where the work begins.
